# 簡報評分表（自評＋獨立 agent 評分）

每份簡報（市場／國際局勢／AI）做完、交給使用者之前都要打分。
目的是找出**這個 Skill 本身**哪裡要改，不是替這份簡報辯護。

## 誰來打分

1. **主分析者自評**：寫完簡報後，照下面四項各打 1–5 分，每項寫一句理由並指出扣分的頁數。
2. **獨立 agent 評分**：另開一個 subagent（可沿用當天做雙向挑戰的那位，但要在新的交辦裡做），
   只給它：簡報 PDF 或 HTML、對應框架、本評分表。**不要給主分析者的自評分數。**
3. 兩邊同一項差 **2 分以上**，列入「分歧」，在修改案裡說明是誰看錯、或是規則本身不清楚。
4. 使用者事後指出的錯誤，記為**使用者更正**，直接扣分（見下方），而且優先於兩邊的評分。

## 四個評分項目

| 項目 | 5 分 | 3 分 | 1 分 |
|---|---|---|---|
| **A. 事實正確** | 數字、日期、時區、程序階段都核對過原始來源，沒有錯 | 有 1 處小錯（不影響結論），或有未標明的未核對數字 | 有錯誤影響結論，或把轉述寫成事實 |
| **B. 來源可靠** | 每個主要主張都追得到原始來源（官方、公司 IR、交易所、一手報導）；轉述與【僅標題】都標清楚 | 主要主張有一半以上只靠二手轉述；或有來源沒寫 | 主要主張靠單一不明來源、或只看到標題就當證據 |
| **C. 推論完整** | 每個結論都有候選解釋、證據、判別條件；沒有跳步；信心程度寫清楚 | 有 1–2 處從現象直接跳到結論，或沒寫競爭解釋 | 結論沒有證據鏈，或把相關當因果 |
| **D. 討論框架遵守** | 真的先各自獨立再交流；有最強反對意見與它的去向；雙方一致沒被當成多一份證據；框架步驟都走完 | 有走流程但某一步草率（例如反對意見很弱、漏一步） | 沒開 agent、先給了結論再請 agent 挑戰，或框架步驟缺一半以上 |

另外檢查簡報規格（`deck-requirements.md`）：缺「一句話結論」「追蹤表」「來源清單」任一項，
**C 或 B 最高只能 3 分**，並在修改案裡記一條。

## 使用者更正怎麼記

- 使用者指出事實錯誤：該份簡報 A 項 −1（同一份最多扣到 1 分）。
- 使用者指出來源有問題：B 項 −1，並在 `source-registry.md` 那個來源記一次「被更正」。
- 使用者指出推論跳步或沒想到的解釋：C 項 −1。
- 都要寫進當天評分紀錄的「使用者更正」欄，用使用者自己的話。

## 每天的評分紀錄格式

存在 `HOME_DIR/紀錄/評分/YYYY-MM-DD-scorecard.md`：

```markdown
# YYYY-MM-DD 評分紀錄（循環第 N 天）

| 簡報 | 項目 | 自評 | agent | 分歧 | 理由／扣分頁 |
|---|---|---|---|---|---|
| 市場 | A 事實正確 | 4 | 4 | | p.5 台股收盤數字未核對證交所 |
| 市場 | B 來源可靠 | … | … | | |
| … | | | | | |

## 使用者更正
- （時間）「使用者原話」→ 扣哪一項、哪一份

## 這次用到的來源
- 來源名稱｜用在哪一份、哪一頁｜原始／轉述／僅標題｜有沒有被更正

## 規格檢查
- 一句話結論：有／缺（哪一份）
- 追蹤表：有／缺
- 來源清單：有／缺
- 做簡報前有沒有先和使用者討論：有／沒有
```
