# AI 新聞分析框架（修訂版）

- 修訂日期：2026-11-16
- 基礎：沿用〈國際簡報分析框架-修訂版.md〉的常駐底稿、每日四步、出版檢查清單、狀態詞表和標籤詞表。以下只寫 AI 新聞的增補和差異。

---

## 核心原則

- 不只查消息是不是真的，還要查**這些數字和案例能支持推論到哪裡**。
- AI 框架做得好，有時代表**認出這則其實不是 AI 新聞**（例如只是融資、公司治理或個資案），然後就此打住，不往下延伸。
- 「所讀材料沒寫」不等於「沒有發生」，也不等於「公司沒公開」或「還沒執行」。

---

## 一、共用追蹤表與追蹤狀態

- 國際、AI、市場三份簡報**共用同一張追蹤表**，記錄事件、來源和核對狀態；各份簡報的分析主張各自保留，不自動沿用別份的結論。
- 每筆要記：**被哪些簡報引用**，以及**一旦更正會影響哪些主張**。
- 跨簡報引用必須追得回原始來源；簡報之間互相引用，不算多一份證據。
- 每天優先處理今天相關、到期、有重大更正的項目，另外照常掃描新事件。

### 追蹤狀態

| 狀態 | 意義 |
|---|---|
| 追蹤中 | 近期還有要處理的資料、事件或期限 |
| 降頻 | 改成每週、每月或特定事件發生時才查；寫明頻率和理由 |
| 休眠 | 暫時不例行檢查，但要寫好什麼情況下重新啟動 |
| 結案 | 這項檢核已完成、取消，或被其他項目取代；記錄結果和理由 |

- 每次改變狀態，都要寫理由，以及下次檢查或重新啟動的條件。
- 「N 天沒有新消息」只會提醒你去重查，不會自動轉成休眠或結案。N 依議題類型設定（產品傳聞、研究重現、採購、法規期限的節奏都不同）。有期限或還有更正沒處理完的項目，不能進休眠。
- **主張撤回不等於結案**：要確認引用過它的簡報都已經更正，才能結案。

## 二、底稿增補欄位（用得到才填）

| 欄位 | 內容 |
|---|---|
| 技術對象與版本 | 模型、產品、系統的版本；是研究、測試，還是正式部署 |
| 主張題型與卡片結果 | 用哪張主卡、三個問題的簡答、關鍵子主張的核對狀態 |
| 測量定義與條件 | 指標、分母、期間、比較基準、用了多少資源和人力 |
| 驗證方式與適用範圍 | 公司自報、有公開方法、第三方重現，還是實際部署的觀察；能推論到哪裡、不能推論到哪裡 |
| 權限與介入邊界 | 有需要時才填：授權範圍、工具權限、外部輸入、人工介入、實際後果 |
| 關係揭露 | 發布者和研究對象的關係，以及分析工具和當事方的關係 |

- 用不到的欄位就跳過。
- 寫「未知」時，要說明它限制了哪個判斷。
- 發布者公開說明的目的，和別人推測的動機要分開寫；推測動機不是必填欄位。

## 三、每日四步的增補

| 步驟（沿用） | AI 增補 |
|---|---|
| **1. 截止與檢核** | 除了日期，也要檢查版本、測試條件、指標定義、程序階段有沒有變。條件不同的結果，不能串成一個趨勢 |
| **2. 選題與證據** | 問答要先檢核使用者給的前提，再依這則的核心主張選卡。每則只填一張主卡，關鍵子主張分別標核對狀態；選錯卡可以改 |
| **3. 解釋與連結** | 新增另一類核心主張，就要補做那類的檢查；做不到就刪掉，或明確標成待驗證的問題，不能寫成解釋 |
| **4. 影響與觀察點** | 分清能力、可用性、採用、實際成效、商業回報；觀察點要對應到具體主張，不能只寫發布日或財報日 |

---

## 四、六張題型卡

依這則新聞的**核心主張**選卡，不是看標題選。每則一張主卡；只有出現另一類核心主張時才加卡。

| 題型 | 三個必問問題 |
|---|---|
| **1. 能力、評測與產品發布** | ① 哪個版本、什麼任務、可用到什麼程度？② 結果是在什麼工具、資源、人工投入和比較條件下得到的？③ 證據支持到單次展示、可以重現，還是部署後的可靠性？ |
| **2. Agent、安全與事故** | ① 授權範圍、環境邊界和實際後果是什麼？② 模型、使用者、外部輸入、工具配置各起了什麼作用，證據在哪？③ 這是個案，還是有分母的系統性結果？適用哪些版本和環境？ |
| **3. 工作、效率與採用** | ① 這個指標實際量的是什麼？② 比較時有沒有算進品質、人工審核、返工和完整成本？③ 樣本和研究設計允許推論到哪個範圍、哪種因果？ |
| **4. 算力、能源與基建** | ① 說的是訂單、額定容量、已交付，還是實際可用的供給？② 成本和效能是依什麼工作負載、利用率和系統條件比的？③ 關鍵依賴或瓶頸有什麼證據？缺資料會限制哪些結論？ |
| **5. 財務、交易與公司治理** | ① 是傳聞、意向、承諾、批准，還是已經完成？誰有決定權？② 金額、估值、財務或治理說法的範圍和口徑是什麼？③ 哪份文件或哪個行動能確認資金、控制權或營運真的改變？ |
| **6. 資料權利、政策與法律** | ① 涉及哪些產品、用途、地區和對象？真的跟 AI 有關嗎？② 目前在哪個程序階段，具體要求是什麼？③ 哪些行為已經改變、哪些還只是要求或預期？什麼時候可以檢核？ |

- 三個問題是**最低限度的檢查**，答完不代表驗證完成；不能為了填滿答案而推測。
- 刊出前，用標題和關鍵句子反過來對照卡片的答案：卡片填完，不代表可以寫出強結論。

## 五、關係揭露與對稱檢驗

- **製作說明**：寫出實際使用的分析工具和它的開發商。
- **單則註記**：開發商就是這則的當事方，或這則拿開發商和它的直接競爭者比較時，該則另外加一行註記。註記不佔證據標籤的名額，而且要寫實際用的工具，不能套模板。
  - 例：「＊本則由〔使用的工具〕整理，〔開發商〕為本則當事方。」
- 對每家公司用**同一套證據標準**。揭露關係，不代表要額外編出負面解釋。
- 核心的能力或效益主張，不能只靠公司自述就確認；沒有外部證據時，要寫明限制。
- 換另一家公司的模型覆核一次，不算獨立驗證。
- 如果要分析發布者的動機，要另外舉證；不能因為時間點很接近，就推定動機。

---

## 六、問答規則

- 使用者的提問要先拆成三部分：**可以查證的前提**、**真正要問的問題**、**個人偏好或價值判斷**。
- 錯的前提要更正，不明確的前提要限定範圍，假設性的問題要保留條件；不能先全盤同意，再補一段反面說法。
- 「同意」可以用，但要先檢核過，並說清楚同意的是哪一部分。
- 問答頁跟當天的新聞分開標示；問答篇幅長，不代表那則新聞比較重要。
- 問答裡出現的因果和能力主張，一樣要過題型卡的檢查；問答中發現的更正，要同步到共用追蹤表和相關簡報。

## 七、出版檢查增補

在國際框架的出版檢查清單之外，再加上這些：

- [ ] 替代指標不能改名成成果（例如 agent 工時不等於產出）；比例下降不等於人數下降。
- [ ] 輸出量、品質、生產力、商業回報分開寫；個案不直接推到整體。
- [ ] 分清四件事：公司自報、第三方重現、結果是否正確、能力該歸功給誰。
- [ ] 摘要裡保留重要的版本、環境、授權和階段限制，不要在跨頁整理時弄丟。
- [ ] 意向、承諾、交付、可用、實際成效，不壓縮成同一個階段。
- [ ] 類比或換算如果可能誤導核心判斷，就補上關鍵限制或改寫，並保留計算假設。
- [ ] 反方處理的結果，要反映在標題、主張範圍或可信程度上，不能列出來就算了。
- [ ] 「所讀材料沒寫」不能寫成「公司沒公開」「沒有發生」或「還沒執行」。
- [ ] 不因為當事方是 AI 公司，就加上證據不支持的 AI 訓練、能力或市場推論。
- [ ] 證據標籤反映這次實際拿到的材料。例如根據的是別人的轉述，就要加【轉述】。

---

## 八、狀態與標籤

- 沿用國際框架的主張狀態、證據核對、工作狀態和證據標籤。
- 第一節的追蹤狀態另外列，不跟主張狀態混在一起。
- 「問答」是內容類型，關係註記是製作資訊，兩者都不佔證據標籤的名額。
